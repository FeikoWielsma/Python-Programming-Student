Exercise 1 : Python Tooling

This exercise takes about fifteen minutes and leaves you with a working Python 3.14, the uv project manager, the ruff linter and an editor that understands Python. Everything you do in the rest of the course runs in the project you build here.

Step 1 : Install uv

uv is the project manager the course uses, and it can install Python itself, so it is the only thing you install by hand. On Windows, run this in PowerShell :

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

On macOS or Linux, run this in a terminal :

curl -LsSf https://astral.sh/uv/install.sh | sh

Close and reopen the terminal afterwards so that uv is on your PATH, then confirm it works with uv --version.

See also : https://docs.astral.sh/uv/

Step 2 : Install Python

Let uv fetch the interpreter the course uses :

uv python install 3.14

This needs no administrator rights and leaves any Python already on the machine alone. Confirm it with uv python list.

Step 3 : Install an editor

Install Visual Studio Code from https://code.visualstudio.com, then add two extensions from the Extensions panel, the square icon on the left :

  • Python, published by Microsoft
  • Ruff, published by Astral

Any editor works, but the course demonstrates VS Code and the slides assume it.

See also : https://docs.astral.sh/ruff/

Step 4 : Create your course project

You write your own code this week in a project of your own, the same way you would at work. From the folder where you keep your work :

uv init course-work
cd course-work

Open that folder in VS Code, then use the Command Palette, Python: Select Interpreter, and choose the interpreter in .venv.

Step 5 : Confirm the toolchain runs

Run each of these from inside course-work :

uv --version
uv run python --version      # prints Python 3.14.x
uv run ruff --version

Then write a first script. Create hello.py in the project :

def greet(name):
    return f"Hello, {name}"


print(greet("Python"))

Run it with uv run python hello.py. You should see Hello, Python.

Step 6 : See the linter work

Run the linter over your project :

uv run ruff check .

It should report nothing. Now break something on purpose. Add an unused import at the top of hello.py :

import json

Run uv run ruff check . again. It reports F401 'json' imported but unused. Notice that VS Code underlines the same line. Remove the import, or let the linter do it for you :

uv run ruff check . --fix

If time permits : look at demos/00a-python-tooling/02_ruff_findings.py, which is written badly on purpose. Run uv run ruff check over it and read every finding before you look at the comments explaining them.

Exercise 2 : Variables and Data Types

In this exercise you build the first version of the calculator application that you will extend throughout the course.

Step 1

Create a directory or project named exercise2. Next create a Python module calculator2.py in this directory and create two variables nr1 and nr2. Assign integer values to them as follows :

nr1 = 16
nr2 = 23

Use your own values if you like. Print the values, the type and the memory location of the variables with :

print (nr1)
print (nr2)
print (type(nr1))
print (type(nr2))
print (id(nr1))
print (id(nr2))

You should see that the type of the variables is <class 'int'>. The id function gives some numeric value which actually indicates the memory address in a default Python implementation.

Now change the values of the variables by assigning them to a new value and print the memory location of the variables again with the id function. Notice that the id of the variables has changed just by assigning them. This illustrates the fact that integer variables are read-only : they cannot change once they are created. When you change an integer variable you actually create a new one.

Step 2

Next perform arithmetic operations on the variables by adding, subtracting, multiplying and dividing them. Store the result of these operations in other variables. An example for the addition operation is :

addresult = nr1 + nr2

Display the results of the operations with an explanatory message :

print ("The result of the addition of : " + str(nr1) + " and " + str(nr2) + " is : ")
print (addresult)

Notice the conversion function str that turns an integer into a string, so that it can be added to other strings.

As an alternative you can also use the string format operator % for printing values in a string :

print ("The result of the addition of : %d and %d is : " % (nr1, nr2))

A third alternative is to use the new style of formatting in Python 3 with the format() function. Figure out using the course manual or documentation how to use this style of string formatting. And a fourth alternative would be to use an f-string. Figure that one out as well.

Also display the types of the results. The first three are of <class 'int'>. Notice that the type of the division is <class 'float'>.

Step 3

Now use the input() function to ask for the input of two numbers from the user as follows :

s1 = input("give me number 1 : ")
s2 = input("give me number 2 : ")

The input() function returns a string. Find out about the type of the return values by printing their type. Now perform addition with the + operator on the user input. With user input 1 and 3 the result will be 13, because 1 and 3 are seen as strings : the strings are concatenated.

addresult = s1 + s2  # s1='1', s2='3'
print (addresult)    # prints 13

Next convert the strings to integers with the int() conversion function as follows :

addresult = int(s1) + int(s2)

With the same input the result will now be 4. When the given input cannot be converted to an int, a runtime error occurs :

ValueError: invalid literal for int() with base 10: 'w'

Exercise 12 : Type Hinting

In this exercise you annotate code you have already written, and let a checker read the annotations for you. Work in the course-work project you created in Exercise 1.

Step 1 : Install the checker

mypy is a development dependency, so add it to the project with the --dev flag :

Step 2 : Annotate a function

Create a module shapes12.py with two functions and no annotations at all :

def area(width, height):
    return width * height

    return f"{name} has an area of {area}"


print(describe("kitchen", area(3.0, 4.0)))

Run it with uv run python shapes12.py and confirm it works. Now annotate both functions. Every parameter takes a colon and a type, and the result takes an arrow :

def area(width: float, height: float) -> float:
    ...

Do the same for describe, which takes a string and a number and returns a string. Run the program again and confirm the output has not changed. Annotations do not alter what the program does.

Step 3 : Let the checker find a mistake

Run the checker over the module :

uv run mypy shapes12.py

It should report nothing. Now introduce a mistake on purpose. Change the last line so that it passes the name and the area the wrong way round :

print(describe(area(3.0, 4.0), "kitchen"))

Run the program. Notice that Python is perfectly happy and prints nonsense. Now run uv run mypy shapes12.py again. The checker reports the mismatch and names the argument that is wrong, without the program having run at all. Put the call back the way it was.

Step 4 : Annotate a collection

Add a function that takes a list of numbers and returns their average :

    return sum(values) / len(values)

Annotate it. The parameter is a list of floating point numbers, written list[float], and the result is a float. Call it with average([1.0, 2.0, 3.0]) and check it with mypy.

Then call it with a list of strings, average(["a", "b"]), and run mypy again. The checker reports the mismatch even though the offending value is inside a list.

Step 5 : A value that may be absent

Add a function that greets someone whose name you may not know :

    if name is None:
        return "Hello, stranger"
    return f"Hello, {name}"

Annotating this as name: str = None would be a lie, because None is not a str. Write it as name: str | None = None instead, and give the function a -> str result. Confirm with mypy that both greet() and greet("Alice") are accepted.

Step 6 : Annotate a class

Take the Employee class from Exercise 11 and annotate its __init__ method. The self parameter is never annotated. A method that returns nothing is annotated -> None :

class Employee:
    def __init__(self, name: str, salary: float) -> None:
        self.name = name
        self.salary = salary

Annotate the other methods as well, then run mypy over the module and fix whatever it reports.

If time permits : run uv run mypy over one of your solutions from an earlier exercise, with no annotations added at all. Notice how little it can say. Then annotate one function and watch how much further it can reason from that single signature.
