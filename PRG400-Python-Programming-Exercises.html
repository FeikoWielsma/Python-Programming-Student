Exercise 1 : Python Intro

Before you can write a game you need somewhere to write it. This exercise installs Python, the uv project manager, the ruff linter and an editor that understands Python, and creates the project you build a Wordle game in for the rest of the course.

There is no starter for this exercise : it is where your own wordle project begins. From Exercise 2 on, every exercise also has a starter folder for when you fall behind.

Every step in this exercise gives you the commands : the point is to see each tool work once.

Step 1 : Install uv

uv is the project manager the course uses. It can install Python itself, so it is the only thing you install by hand. On Windows, run this in PowerShell :

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

On macOS or Linux, run this in a terminal :

curl -LsSf https://astral.sh/uv/install.sh | sh

Close and reopen the terminal afterwards so that uv is on your PATH, then confirm that it works :

uv --version

The documentation is at https://docs.astral.sh/uv/.

Step 2 : Install Python

Let uv fetch the interpreter the course uses :

uv python install 3.14

This needs no administrator rights and leaves any Python already on the machine alone. Confirm it with uv python list, which shows every interpreter uv can see.

Step 3 : Install an editor

Install Visual Studio Code from https://code.visualstudio.com, then add two extensions from the Extensions panel, the square icon on the left :

  • Python, published by Microsoft
  • Ruff, published by Astral

Any editor works, but the course demonstrates VS Code and the slides assume it. The slide Editor Setup lists what the two extensions do for you.

Step 4 : Create the wordle project

You write your own code this week in a project of your own, the same way you would at work. From the folder where you keep your work, run :

uv init wordle
cd wordle

uv init writes a pyproject.toml, a .python-version, a README.md and a placeholder main.py, and makes the folder a git repository; the slide Creating a Project explains each of them. Run the placeholder :

uv run python main.py

The first run creates the project's own environment in .venv, then prints :

Hello from wordle!

Open the wordle folder in VS Code. Then open the Command Palette, run Python: Select Interpreter, and choose the interpreter in .venv. The editor now uses the same Python as uv run.

Step 5 : See the linter work

A linter reads code without running it and reports what looks wrong. Add ruff to the project as a development tool, one the project needs while you write it but not when it runs :

uv add --dev ruff

uv records it in pyproject.toml under [dependency-groups], so anybody who works on the project gets the same tool. The test runner pytest arrives the same way in the libraries appendix, in Exercise 13. Run ruff over the project :

uv run ruff check .

There is nothing wrong yet, so it reports :

All checks passed!

Now write something with a mistake in it. Create hello.py in the project :

import json

Run it with uv run python hello.py. It prints Hello, Python, so Python itself has no complaint. Run uv run ruff check . again. This time ruff reports the import nobody uses :

Step 6 : The word list

A word game needs words. Copy words.txt from exercises/handouts/01-environment-configuration/ into the wordle folder, next to pyproject.toml.

Rename main.py to wordle.py, which is the name the game has from here on, and replace its contents with :

from pathlib import Path


def main() -> None:
    """Print the number of characters in the word list."""
    words = Path("words.txt").read_text(encoding="utf-8")
    print(f"The word list contains {len(words)} characters.")


if __name__ == "__main__":
    main()

Path("words.txt").read_text(...) reads the whole file into one string, and len counts its characters. The rest of the file is the same shape as the main.py that uv init wrote; module 05 explains def and module 06 explains the last two lines. Run it :

It prints :

The file holds one five-letter word per line, so every word takes six characters including its line break. How many words are in the list? Exercise 3 counts them properly.

Step 1 : A secret and a guess

Replace the contents of wordle.py with a fixed secret word and a guess typed by the player :

Step 2 : Letter by letter

For each of the five positions, the game needs the answer to two questions : is the letter of the guess the same as the letter of the secret in that place, and is the letter of the guess anywhere in the secret? Print the answers as a small table, one row per position.

The header and the shape of the first row are given. Fill in the two questions, then add the rows for positions 1 to 4 :

Step 3 : Length, slices and counts

Three more questions about the guess and the secret, each answered in one line :

print(f"Five letters: {...}")
print(f"First two: {...}, last two: {...}")
print(f"The secret contains {...} letter e characters.")

The first is a check the game will need on every guess : does it have five letters? It only prints True or False for now. It does not protect the table of Step 2, which indexes the guess before this line runs, so keep typing five letters. The second takes the guess apart with slices. The third counts how often e occurs in the secret.

Hint : The slide String Operations shows slices, including ones that count from the end, and Built-in String Methods has len and the string methods.

Hint : len gives the length of a string, and comparing it with == gives True or False. A slice word[start:stop] can leave out either end, and a negative index counts from the end : word[-1] is the last letter.

Hint : Strings have a method that counts how often a piece of text occurs in them, and it is named after what it does. You call it on the secret, with the letter as its argument.

Solution 
print(f"Five letters: {len(guess) == 5}")
print(f"First two: {guess[:2]}, last two: {guess[-2:]}")
print(f"The secret contains {secret.count('e')} letter e characters.")

Inside this double-quoted f-string, single quotes make the inner string literal easy to distinguish : 'e'. Python 3.14 also allows double quotes inside the expression.

Step 1 : Six guesses

Exercise 3's script explored the data; this exercise turns it into a game. Replace the contents of wordle.py with :

import os
import random
from pathlib import Path

words = Path("words.txt").read_text(encoding="utf-8").split()
secret = os.environ.get("WORDLE_SECRET", random.choice(words))
max_guesses = 6

print("Guess the five-letter word.")

guess_count = 0
while guess_count < max_guesses:
    guess = input(f"Guess {guess_count + 1}/{max_guesses} : ").strip().lower()
    guess_count += 1
    print(guess.upper())

print(f"The word was {secret.upper()}.")

The while loop runs its indented block again and again for as long as its condition is true. Every pass reads a guess and adds one to guess_count, so after six passes the condition is false and the program carries on below the loop. The slide while Loop shows the shape.

A random secret makes a game you cannot check, so the secret can be fixed from outside the program. os.environ holds the environment variables of the process, and get returns the second argument when WORDLE_SECRET is not set. In PowerShell, set it for the rest of the session :

$env:WORDLE_SECRET = "crane"
uv run python wordle.py

In bash, set it for a single run :

WORDLE_SECRET=crane uv run python wordle.py

The outputs in this exercise all use crane. In PowerShell, Remove-Item Env:WORDLE_SECRET brings the random secret back. Play once : the game takes any six answers, even ones that are not words, and does not yet tell you anything about them.

def score_guess(secret: str, guess: str) -> list[str]:
    """Mark each letter of guess as "green", "yellow" or "grey".

    A letter is yellow only while the secret still has an unmatched copy of it,
    so one E in the secret cannot make two E's in the guess yellow.
    """
    marks = ["grey"] * WORD_LENGTH
    unmatched: list[str] = []

    # First pass : exact matches. Whatever the secret has left over is
    # available to be found elsewhere.
    for position, letter in enumerate(guess):
        if letter == secret[position]:
            marks[position] = "green"
        else:
            unmatched.append(secret[position])

    # Second pass : right letter, wrong place, each copy used at most once.
    for position, letter in enumerate(guess):
        if marks[position] != "green" and letter in unmatched:
            marks[position] = "yellow"
            unmatched.remove(letter)

    return marks

["grey"] * WORD_LENGTH builds a list of five "grey" strings, so every letter starts grey and only the two loops change that.

def follows_hints(guess: str, history: list[tuple[str, list[Mark]]]) -> bool:
    """Return whether guess keeps green letters and includes yellow ones."""
    for previous, marks in history:
        for position, (letter, mark) in enumerate(zip(previous, marks, strict=True)):
            if mark == "green" and guess[position] != letter:
                return False
            if mark == "yellow" and letter not in guess:
                return False
    return True

def save_game(
    secret: str, history: list[tuple[str, list[Mark]]], max_guesses: int, hard: bool
) -> None:
    """Write the secret, the scored guesses and the game's settings to the save file."""
    data = {"secret": secret, "history": history, "max_guesses": max_guesses, "hard": hard}
    SAVE_PATH.write_text(json.dumps(data, indent=2), encoding="utf-8")


def load_saved_game() -> tuple[str, list[tuple[str, list[Mark]]], int, bool] | None:
    """Read a saved game, returning None when no save exists."""
    if not SAVE_PATH.exists():
        return None
    data = json.loads(SAVE_PATH.read_text(encoding="utf-8"))
    history = [(word, marks) for word, marks in data["history"]]
    return data["secret"], history, data["max_guesses"], data["hard"]


def clear_saved_game() -> None:
    """Remove the save after a game is complete."""
    SAVE_PATH.unlink(missing_ok=True)
